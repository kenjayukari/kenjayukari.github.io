2.3 报错：hexo 命令找不到

症状：全局安装 Hexo 后，在 Git Bash 输入 hexo，提示 -bash: hexo: command not found。

原因：系统不知道去哪个目录找 hexo 这个命令，即 npm 全局安装目录没有加入 PATH。

解决办法：

  • 把 npm 的全局模块存放路径（node_global 对应的目录）加入环境变量 PATH，然后重启 Git Bash。
  • 如果还不行，在 hexo 前加 npx：npx hexo，后面正常追加参数。

[!note] 小白补充
Windows 下 npm 全局可执行文件通常在：
C:\Users\你的用户名\AppData\Roaming\npm
把这一层目录加入 PATH 后，终端才能直接识别 hexo 命令。

2.4 图片问题：什么是图床

Markdown 里的图片是“引用”的。文章里写 ![](图片链接)，部署到博客后，浏览器要能通过网络访问到这张图。

如果图片只在本地电脑上，别人打开你的博客就看不到。解决办法是把图片传到图床，拿到一个网络图片链接。

推荐：

  • 注册阿里云账号。
  • 参考 阿里云OSS PicGo 配置图床教程 配置阿里云 OSS。
  • 用 PicGo 上传图片并得到链接。

[!note] 小白补充

  • 阿里云 OSS 就像一块“云上的硬盘”，按用量收费；原文建议博客访问量低时不用买流量包、储存包，充值几块钱用默认配置即可。
  • PicGo 负责“上传图片 + 自动复制链接”，你只需要把链接粘到 Markdown 的 ![](链接) 里。
  • 原文还提到：不推荐再用 GitHub / Gitee 当免费图床，前者访问慢，后者政策限制多。

3.1 文章链接没有生效 / 404（hexo-abbrlink）

原文背景

Hexo 默认的文章链接规则是 :year/:month/:day/:title。

如果文章标题是中文，生成的链接会变成很长一串 URL 编码字符，很难看。可以使用 hexo-abbrlink 插件，在文章 Front matter 中写自定义短链接：

安装方式参考：Hexo+Github 博客 butterfly 和 matery 主题 搭建完全教程

遇到的问题

原文把 abbrlink 从 Basic-CSS3-knowledge 改成 Basic-CSS3-Knowledge 后，执行：

但线上链接仍是旧地址，点击文章出现 404。

原因

abbrlink 会作为文件夹名生成链接。Git 默认不追踪文件夹名称的大小写修改，所以只改了文件内容，线上文件夹名没变。

推荐解决办法

  1. 先在 _posts 中移除这篇文章。
  2. 部署一次博客。
  3. 把文章重新放回 _posts。
  4. 再部署一次博客。

[!note] 小白补充

  • Front matter 就是文章最顶部 --- 之间那段元信息。
  • 404 表示“页面不存在”：链接变了之后，旧地址自然打不开。
  • 如果已经发布过文章，尽量不要随意改永久链接，否则旧链接会失效。

3.2 社交图标和分享按钮不显示

症状

侧边栏社交图标、文章页分享按钮在电脑浏览器上看不到，但在手机浏览器上正常。

原因

不是主题问题，而是电脑 Chrome 安装了广告拦截插件 AdGuard，把图标和按钮误拦了。

解决

  • 不使用 AdGuard；
  • 换用 AdBlock；
  • 或自定义 AdGuard 的拦截规则，放行网站内容。

[!note] 小白补充
广告拦截插件按规则隐藏网页元素，有时会把网站自己的图标、搜索框一起误伤。遇到“电脑不行、手机正常”的情况，先关掉浏览器插件试试。

原文还提到：AdGuard 同样导致本地搜索插件被拦截，排查了很久才发现是插件的问题。

hexo g（generate） 生成静态网站文件
hexo s（server） 本地预览，默认 http://localhost:4000
hexo d（deploy） 部署到远程（如 GitHub Pages）
npm install 包名 --save 安装插件并写入 package.json
npm un 包名 --save 卸载插件
node -v / npm -v 查看 Node.js / npm 版本
git --version 查看 Git 版本
